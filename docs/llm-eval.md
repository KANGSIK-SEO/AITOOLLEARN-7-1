# LLM 답변 품질: 개선 방법과 측정 방법

## 1. 품질을 높이기 위해 한 것

| 문제 | 대응 | 코드 |
|---|---|---|
| AI가 없는 그림·작가·연도를 지어낸다 | **검색과 답변을 분리**: AI는 검색어만 뽑고(1단계), 그림은 DB에서 찾고(2단계), 답변은 찾은 목록 안에서만 쓰게 한다(3단계 규칙 1) | `app/chat.py` |
| AI 출력 형식이 깨진다 | 검색 조건을 **JSON 한 개**로만 받고, 깨진 JSON·잘못된 타입은 안전한 기본값으로 정리 | `chat._parse_intent` |
| "고흐 1950년" 같은 조건이면 결과가 0개 | 작가·연도를 빼고 **검색어만으로 다시 찾고**, 그 사실을 답변 첫 줄에 알리게 한다(규칙 6) | `chat.find_artworks` |
| 용도와 안 맞는 추천 | 질문에서 **용도·비율**을 뽑아 비율 필터를 켜고, 작품마다 용도에 맞는 이유를 설명(규칙 7) | `INTENT_SYSTEM`, `ANSWER_SYSTEM` |
| 결과가 100개면 답변이 잘리고 비싸다 | 본문 설명은 **6개까지만**, 나머지는 카드로 | `ANSWER_NARRATION_LIMIT` |
| 매번 같은 그림만 나온다 | 상위 2개는 고정, 나머지는 후보에서 **무작위로 섞기** | `art._diversify` |
| 공신력을 과장한다 | "보증·인증" 금지, 근거 기록 발급 안내(규칙 8) | `ANSWER_SYSTEM` |
| 이전 대화를 모른다 | 같은 사용자의 최근 5개 Q/A를 프롬프트에 포함 | `CONTEXT_TURNS` |

## 2. 측정 방법

`scripts/eval_llm.py` — 질문 **20개**(용도·비율·작가·잡담·영어 질문 섞음)에 실제 AI를 돌려 자동 채점한다.

```bash
python3 scripts/eval_llm.py --dry-run   # 채점기 점검 (가짜 AI, 비용 0)
python3 scripts/eval_llm.py             # 실제 평가 (GPT_ASTRA_API_KEY 필요, 약 40회 호출)
```

**정량 지표**
| 지표 | 무엇을 보나 |
|---|---|
| 의도 추출 정확도(%) | 잡담 여부·비율·용도·검색어·작가를 기대값과 비교 |
| 근거성(grounded) | 답변의 `[n]` 인용이 실제로 넘긴 작품 번호 안에만 있는가 — **환각 탐지** |
| 한/영 병기 | `English:` 섹션 존재 |
| 금지어 | "보증·인증" 미사용 |
| 근거 기록 안내 / 완화 안내 | 규칙 8 / 규칙 6 준수 |
| 평균 지연(ms) | 사용자 체감 속도 |

**정성 평가** — 결과 JSON(`data/eval/llm-eval-*.json`)의 답변 원문을 팀원 2명이 읽고 사례마다 1~5점
("용도에 맞는 설명인가", "읽기 쉬운가")을 매겨 평균을 낸다.

**사용 원칙** — 프롬프트(`INTENT_SYSTEM`, `ANSWER_SYSTEM`)를 바꿀 때마다 평가를 다시 돌려 이전 결과 JSON과 비교한다.
점수가 떨어지면 되돌린다. 자동 테스트(`tests/test_eval_llm.py`)는 채점기 자체가 틀리지 않는지 확인한다.
