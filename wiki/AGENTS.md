# 위키 운영 규칙 (LLM이 읽고 따르는 스키마)

이 폴더(`wiki/`)는 **LLM이 쓰고 고치는 프로젝트 지식 베이스**다 (LLM Wiki 패턴).
사람은 질문하고 방향을 정하고, LLM은 원본(코드·문서)을 읽어 위키 페이지를 만들고 최신으로 유지한다.

## 3개 층

| 층 | 위치 | 누가 고치나 |
|---|---|---|
| 원본(raw) | 저장소의 코드·문서 (`app/`, `scripts/`, `docs/`, `tests/`, `.github/`, `README.md` 등) | 개발자. 위키 작업 중에는 **읽기만** 한다 |
| 위키 | `wiki/*.md` | LLM. 원본에서 정리·요약·연결한 페이지 |
| 스키마 | 이 파일 `wiki/AGENTS.md` | 사람과 LLM이 합의해서 고친다 |

## 페이지 형식

모든 페이지(이 파일, `index.md`, `log.md` 제외)는 맨 위에 아래 머리말을 둔다.

```
---
title: 페이지 제목
sources: [app/chat.py, docs/rights-policy.md]   # 이 페이지가 근거로 삼은 원본 파일 (실제로 있어야 함)
updated: 2026-10-07
---
```

- 본문은 **한국어, 쉬운 말**로 쓴다. 코드를 모르는 사람이 읽어도 "무엇을, 왜"가 보여야 한다.
- 사실마다 근거 파일을 `app/chat.py`처럼 백틱으로 적는다. 원본에 없는 내용은 쓰지 않는다 (추측 금지).
- 다른 위키 페이지는 상대 경로 링크로 잇는다: `[권리 판단](rights.md)`.
- 숫자(작품 수, 제한 값 등)는 바뀔 수 있으니 어디서 읽었는지 함께 적는다.

## 작업 3가지

1. **ingest (반영)**: 코드나 문서가 바뀌면
   - 바뀐 원본을 읽고, 관련 페이지를 고친다 (한 변경이 여러 페이지에 걸칠 수 있다).
   - 새 주제면 페이지를 만들고 `index.md`에 한 줄 추가한다.
   - `log.md` 맨 아래에 `## [날짜] ingest | 무엇이 바뀌었나` 한 줄을 붙인다.
2. **query (질문)**: 질문을 받으면 `index.md`부터 읽고 관련 페이지를 찾아 답한다.
   좋은 답(비교·분석)은 새 페이지로 남기고 `log.md`에 `query` 항목을 붙인다.
3. **lint (점검)**: `python3 scripts/wiki_lint.py`를 돌려 고친다.
   - 깨진 링크, `sources`에 없는 파일, `index.md`에 빠진 페이지를 자동으로 찾는다.
   - 사람이 볼 것: 서로 모순되는 페이지, 코드와 달라진 설명, 고아 페이지(아무도 링크하지 않음).

## 지키지 않을 것

- 비밀 값(API 키, 토큰, `.env` 내용)은 위키에 절대 적지 않는다. 변수 **이름**만 적는다.
- 개인 이메일 주소는 적지 않는다. 팀원은 이름과 GitHub 아이디만 쓴다.
