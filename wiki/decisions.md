# 주요 결정과 그 이유

새 결정은 맨 아래에 붙인다. 형식: 날짜 · 결정 · 이유 · 관련 페이지.

| 날짜 | 결정 | 이유 | 관련 |
|---|---|---|---|
| 초기 | 작품 DB(SQLite 파일)와 사용자 DB(Turso)를 나눈다 | 서버리스는 파일 쓰기가 유지되지 않는다. 안 바뀌는 데이터는 파일로 빠르게, 바뀌는 데이터는 외부 DB에 | [데이터베이스](database.md) |
| 초기 | AI는 검색 조건 만들기와 설명만, 작품은 DB에서 | AI가 없는 작품을 지어내지 못하게 | [질문 처리 흐름](request-flow.md) |
| 초기 | 가디언: 규칙은 즉시, AI 분석은 하루 한 번 | 요청마다 AI를 부르면 비용이 공격 수단이 된다 | [가디언](guardian.md) |
| 초기 | 병합은 merge commit만 | 팀원별 커밋 10회 기록 보존 | [팀과 작업 방식](team-process.md) |
| 개발 중 | 퍼블릭 도메인 "추정" 금지, 기관이 작품마다 CC0라고 밝힌 것만 | "저작권 걱정 없는" 서비스에서 한 작품이라도 틀리면 전체 신뢰가 무너진다 | [권리 판단](rights.md) |
| 개발 중 | 추천 기준을 "명화"에서 "용도"(카페·교재·PPT·SNS)로 | 취미가 아니라 돈 내고 쓸 손님의 문제를 풀기 위해 | [AI 호출](ai-llm.md) |
| 개발 중 | "확인서" → **"권리 근거 기록"**, 인터넷 아카이브 보관 추가 | 공신력 있는 직인이 없는 문서를 확인서라 부르면 오해. 제3자 보관본이 더 믿을 만하다 | [권리 근거 기록](records.md) |
| 2026-10-07 | 비로그인 3회 체험 **제거** | 미션 요구사항: "챗봇 질문/응답은 로그인한 사용자만" | [로그인과 보안](auth.md) |
| 2026-10-07 | 운영 배포는 **main에서만** | 기능 브랜치에서 직접 배포하던 것을 feature → develop → main 흐름으로 바로잡음 | [배포와 CI](deploy-ci.md) |
| 2026-10-07 | 화면 파일에 내용 해시(`?v=`)를 붙여 캐시 무효화 | 서비스워커가 옛 `app.js`를 계속 보여줌 | [화면](frontend.md) |
| 2026-10-07 | Turso 문장들을 요청 한 번으로 묶기 | 로그인·채팅이 느리다는 사용자 피드백. 왕복 12회→1회, 4회→1회 | [데이터베이스](database.md) |
